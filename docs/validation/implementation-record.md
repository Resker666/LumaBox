## Rulings I made

按实施顺序保留全部取舍及判断错误的代价：

1. 在用户新建的干净仓库特性分支原地实施；符合已批准范围。若判断错误，需要迁移 checkout。
2. Windows Bash 辅助脚本缺少 basename/dirname，改用等价原生任务记录与账本，不改用户环境配置。若判断错误，需要校正记录。
3. 网络测试夹具随消费测试保存，暂不创建空 helpers 模块。若判断错误，后续提取共享夹具。
4. 内部支持实际观察到的 `/jingxuan?modal_id=` 作品视图，并核对活动 DOM ID；输入仍限定完整 video/note/短链。若判断错误，某些页面视图会被拒绝。
5. 无法证明完整顺序的虚拟化图集明确失败，不猜测下一张入口。若判断错误，部分图集暂不支持。
6. 编辑安装实际暴露缺失 bdist_wheel，补充 wheel 构建依赖。若判断错误，多一个构建依赖。
7. 同步传输增加可选取消事件，保留默认接口；取消 asyncio future 不能终止线程。若判断错误，取消需等待阻塞操作；最终修复已可中断 HTTP 读取。
8. 取消后等待工作线程退出再清理，FFmpeg 验证仍有180秒上界。若判断错误，取消较慢。
9. 实际执行跨过日期边界，真实报告命名为2026-10-13。若判断错误，需要修正文档链接。
10. 审查不判断真实平台 DOM/下载结果：真实请求在HTTP前停止，因此仅报告合成流程成功和只读DOM依据，真实P0未通过。若判断错误，后续真实复测可能需要适配页面。
11. 审查不判断无头/Linux：仅提供运行入口，不宣称这些环境下载成功。若判断错误，需补依赖或平台适配。
12. 审查不判断未观察到的虚拟化布局：只接受已观察且能由计数器与水平几何位置确认的完整布局；新布局无法证明即拒绝。若判断错误，部分作品不支持，需在真实环境再验证。
13. DNS与会话头的不可中断系统调用在守护线程中运行并有界等待；超时后不能开始后续下载或写文件，底层DNS调用可能稍后自行结束。若判断错误，进程结束前短时占用线程资源。
14. 依用户批准范围保留本地特性分支；真实P0未通过，没有远程仓库或可合并的main分支，不增加推送/合并确认流程。若判断错误，用户后续需指定集成方式。
