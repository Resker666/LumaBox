## 原因与修复

通过正常匿名浏览器只读检查相同作品，确认了旧实现未覆盖的专用详情布局，并以真实 Chromium 合成页面复现：

- 视频：详情播放器没有 `feed-active-video` 作品祖先，实际作品 ID 位于播放器语义类 `video_7686430330920075249`。新实现要求唯一 `[data-e2e="video-detail"]` 区域、唯一详情播放器、唯一语义作品 ID 和唯一内部播放器，并与当前页面目标匹配。
- 图集：详情播放器和活动作品侧栏是同一个 `[data-e2e="note-detail"]` 区域的不同分支。新实现从同区域唯一 `.noteSideBarContainer` 的唯一活动节点读取实际作品 ID；不再要求该节点必须是播放器祖先。旧的祖先布局仍支持。
- 详情区域的 HTML 标签可为 `main` 或 `div`，定位依据为 `data-e2e` 语义标记。多个可见详情区域、播放器或活动侧栏条目均拒绝。
- 旧登录识别会把“请先登录后发表评论”等评论要求当成观看要求。现在只识别明确的观看/访问登录要求，并处理文本中的空白。已确认作品区域中的非空 blob 来源计为正在提供媒体，继续有界等待 HTTPS；不会仅因该来源不是 HTTPS 而提前判为登录失败。

新增诊断字段 `scope_confirmed`、`identity_source`、`media_schemes`，分别说明作品区域是否确认、DOM 身份来源及媒体协议。字段不包含完整媒体 URL、签名、Cookie 或原始页面正文。公网地址策略、域名边界、挑战停止和完整媒体校验没有放宽。

- 回归测试先复现登录误判、视频和图集定位失败，以及标签差异造成的失败；修复后完整测试：**132 passed in 46.21s**，退出 0。新增 23 项用例覆盖专用详情、错误或缺失作品 ID、多区域歧义、无关推荐、登录提示、blob 等待及脱敏诊断。
- 真实图集只读复查：实际 DOM ID 为 `7695689642767235187`，计数 12，几何位置序号完整为 1～12；12 个前景来源均为 HTTPS，主机 `p3-pc-sign.douyinpic.com`。这是资源定位证据，不是独立 CLI 下载成功。
- 真实视频只读复查：实际 DOM ID 为 `7686430330920075249`，作品区域和单个播放器确认，来源仍为 `blob:`，没有 `<source>` 提供 HTTPS。播放器能够播放 124.6 秒的视频，不能据此认定当前 DOM 提取方案能取得完整文件。持久 blob 会在资源等待上限后返回 UNSUPPORTED_MEDIA，原因是没有普通 HTTPS 媒体来源。
- 修复后的正式 CLI 依次复测两个授权样本：均在初始 DNS 阶段返回 UNSAFE_TARGET（非公网目的地址），HTTP 状态为空，未下载文件。该执行环境与用户已获得 HTTP 200 的正常网络运行不同。
