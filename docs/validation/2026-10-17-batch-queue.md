# 0.7.0 批量提交与队列管理验证

日期：2026-10-17。用户选择下一版方向 A。本轮在原目录的 `feat/batch-queue` 分支开发，更新本地体验服务；云端继续运行已验收的 0.6.0。

## 使用行为

- 输入框支持一次粘贴最多 10 条链接或含链接的分享文案，显示识别数量。重复和无效 URL 都计入 10 条上限；分享文案最多 4096 字，请求体仍受原有 8192 字节限制。
- 批量提交逐条返回已加入队列、已在队列、已收藏、链接无效或队列已满。空位不足时按输入顺序接收能够排队的项，不撤销前面已接收的任务。
- 等待队列保持最多 10 项，下载与音频仍由单个 worker 串行执行，没有增加并行浏览器。
- “进行中”的“管理待下载”默认折叠，只能选择 pending 任务。批量取消不会取消已开始的下载、自动重试等待或独立音频任务；状态变化后逐条提示跳过。
- 历史的“批量重试”默认折叠，只能选择当前页未完成、已取消、已过期记录。沿用各任务原来的视频大小上限和音频选项，不使用当前输入框的设置，也不强制重复下载。
- 两个区域共可选择 10 项。轮询保留勾选、展开和焦点；任务离开可操作状态后移出选择，切换历史搜索、筛选和页码会清空历史选择。
- 部分未接收链接保留在输入框。请求期间编辑的新草稿不会被响应覆盖，未接收链接可从结果中追加回填；随后批量取消或重试也不会清空回填缓存。
- 复用已收藏作品不会自动修改其音频选项或恢复隐藏记录，用户可以选择“恢复并查看”或在已有视频中明确提取音频。

## 接口与旧数据兼容

新增 `POST /api/jobs/batch`、`/api/jobs/batch/cancel`、`/api/jobs/batch/retry`，复用既有队列、判重与逐任务状态，不新增批次数据库或第二套执行流程。原单任务接口保持可用。

批量操作保留 Origin、Host、CSRF、云端登录和请求体大小检查。整批字段、数量或 ID 格式不合法时不产生部分修改；合法批次中的重复、无效链接、已变化任务和容量不足分别返回逐项结果。存储中不保存原分享文案、跟踪参数或非法链接中的凭据。

未知短链接可能在开始处理后才确认作品身份。新增内部持久化字段 `supplement_duplicate_audio`，批量提交和批量重试设为关闭，避免后置判重自动改变旧收藏的音频。旧数据库升级默认开启，保留 0.6.0 单任务行为；普通重试继承原任务策略。该字段不接受公共 API 设置。

首轮完整回归为 643 passed、1 failed、1 skipped、2 warnings。唯一失败是 `test_launcher_help_exposes_only_local_options`：本轮测试命令设置 `PYTHONIOENCODING=utf-8`，子进程输出 UTF-8，而旧测试通过 Windows 默认 GBK 解码。移除这个测试环境覆盖后，该项单独通过；没有为此修改启动器或测试代码。

审查发现并通过先失败后修复的回归关闭两个问题：后置短链判重可能自动给旧收藏补音频；批量取消 / 重试可能覆盖之前提交的未接收链接缓存。最终后端与前端只读复审未发现新的确定重要问题。
