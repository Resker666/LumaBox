# 日常使用体验验证

用户选择方向 B，并批准具体行为后要求执行：Windows 一键启动、作品标题、真实下载进度、视频/图集预览、历史搜索筛选分页和移除记录。历史移除保留全部已下载文件。基线为 v0.3.0 / 6b2757e，实施分支为 feat/daily-use，当前源版本 0.4.0；本轮不合并或推送。

## 实现范围

启动器等待本项目的服务就绪，验证应用标识、版本和数据/保存目录后才复用端口；启动锁避免重复创建服务。Windows 后台进程不弹出下载终端，网页使用默认浏览器；原下载 Chromium 仍按已有有界面方式运行。启动器不安装依赖，不结束未知服务。默认浏览器打开动作在自动化中作为叶节点替代，实际启动与 HTTP 验证使用真实子进程。

标题来自已确认作品区域中的唯一可见标题，或已绑定相同作品 ID 的正常详情描述，归一化为最多 300 字。缺少标题时保留 ID，旧记录不会自动重新请求抖音。标题通过 textContent 显示，不能作为 HTML 执行。

进度快照只包含阶段、作品身份、标题、接收字节和数量；有界原子替换，不追加进程标准输出，也不记录资源地址或 Cookie。媒体传输回调记录实际写入字节，图集总字节未知时使用字节和图片数。Web 仍须通过原有最终报告、文件、数量和 SHA-256 检查后才发布成功；进度不能提前代表成功。

预览使用已发布文件的 ID，支持 GET/HEAD 和单段 byte Range、尾部范围、206/416，持有文件访问租约。响应中断或发送失败也释放文件；ZIP 不作为媒体预览。预览界面在任务列表之外，轮询不会重建播放器；关闭会移除媒体 src。

历史搜索使用参数化查询并按字面匹配百分号/下划线，返回总数和分页。移除只设置隐藏标记，拒绝等待/运行任务，隐藏记录的网页访问变为 404；已保存媒体、正在读取的租约及目录迁移保持有效。清理失败只隐藏失败任务。

## 原有用户数据与证据边界

升级前旧服务没有活动任务，已在 WebData/backups 创建 SQLite 备份。核对 PID、创建时间、命令和父进程后停止旧服务，再通过新启动器启动 0.4.0。原有 8 条记录保留，现有成功视频和图集继续保存；自动化测试及审查只修改临时数据。

新版实际服务已验证原有视频和图集预览：117,637,046 字节视频的 HEAD 和 206 byte Range 正确，真实 Chromium 加载 960.149 秒视频、播放并定位到 480 秒，确认定位后可解码；原有图集 12/12 张可顺序浏览，关闭预览后释放媒体源。此过程仅访问本机 HTTP，没有请求抖音、改写媒体或创建测试历史。

0.3 已实测成功的 16 分钟视频和完整 12 张图集是媒体下载基线证据。本轮标题与实时进度尚没有新的真实抖音下载证据，用户可在正常使用时再验收。Linux、无头下载和公网部署不在本轮验收范围。
