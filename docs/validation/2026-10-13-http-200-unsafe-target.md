# HTTP 200 后 UNSAFE_TARGET 诊断

2026-10-13，用户在正常网络下用正式 CLI 运行两条授权样本，保留报告如下：

| 样本 | 运行ID | 主页面HTTP | metadata_parsed | 结果 |
|---|---|---|---|---|
| 视频 | `41dcfb71ca4044eebaf214099e58e995` | 200 | false | UNSAFE_TARGET |
| 图集短链 | `bd05949038374947a59c07833e26f9b6` | 200 | false | UNSAFE_TARGET |

和此前HTTP状态为空不同，这两次已通过初始域名的公网解析并获得主框架响应，在 `BrowserSession.load()` 完成之前失败；未开始文件下载。HTTP 200不等于页面已提供可用的媒体资源，也不能用来判断登录是否必要。

## 确认的程序缺陷

原实现将 CDP `Document` 请求全都当成整个作品的主导航；iframe同样属于Document。当外域子框架被地址策略拒绝，代码会写入共享 `self.error`，随后主作品也被判为UNSAFE_TARGET。原 `_check_errors()` 还会在页面加载成功后，把同域后台连接失败当作整个页面失败。

用真实 Chromium 的合成页面确认了这两条错误路径。主页面返回200、作品ID和视频资源合法，加入一个被禁止的 `sso.douyin.com` 子框架就会失败。该域名是回归夹具，**未证实用户真实页面本次请求了它**。后台失败测试同样复现。

修复：通过CDP主框架ID区别主导航和嵌入文档；不允许的子框架仍使用 `Fetch.failRequest` 阻断，但不会设置整个作品的致命错误。只有主页面导航实际失败时，才用对应导航域名的代理错误解释失败。媒体地址与DNS校验继续单独执行，未扩展允许域名。

## 用户这次失败的证据边界

旧报告没有记录触发错误的阶段、原因或域名。上述缺陷可以产生相同的200/UNSAFE_TARGET组合，不能据此断言就是两次真实失败的唯一原因。后续媒体地址域名被拒绝、主导航跳转不符合策略等也能在媒体解析完成前产生该错误。

本会话08:24尝试重复真实诊断时，执行环境已返回非公网DNS地址，两个样本都在HTTP前失败，因此没有复现用户的正常网络状态。08:28正式CLI运行 `8c6ec10f3dc549e29dcf11fd1113472d` 返回：
