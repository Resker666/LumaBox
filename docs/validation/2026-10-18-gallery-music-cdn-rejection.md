# 本地图集配乐域名校验失败分析

日期：2026-10-18。用户反馈本地验证时出现“配乐地址校验未通过”。本次只分析和复现，没有修改生产行为、重置用户任务、部署或推送。

后续用户已授权修复，验证结果另记于[音乐 CDN 修复](2026-10-18-gallery-music-cdn-fix.md)；以下是修复前的原始分析。

## 实际记录

本地任务 `d8d0a9948893453bab3032115ff97799`，图集 `7695689642767235187`：图片下载成功，12/12 张；音频独立失败，错误码 `UNSAFE_TARGET`。用户原图片及任务状态保持不变。

这就是此前成功下载原始 MP3 的同一条图集，单个作品不保证始终返回同一音乐 CDN 主机。

## 复现

1. 首次重新观察：目标作品区域确认，note_sidebar，唯一背景播放器返回 `lf26-music-east.douyinstatic.com`，28.16 秒；当前白名单接受该地址，域名查询返回公网地址。
2. 隔离调用正式配乐原语：复现 `UNSAFE_TARGET`，传回的安全诊断为空。
3. 临时只读跟踪原有 URL 校验，不放宽或跳过检查：同一作品唯一背景播放器返回 **`lf9-music-east.douyinstatic.com`**；`validate_audio_url` 当场抛出 **Audio host has not been verified**，在开始媒体传输前停止。

随后单独查询 lf9 节点，当前返回 3 个公网地址。此次复现明确发生在域名白名单校验，尚未进入该资源的 DNS/连接步骤；这个结果不反推其他时刻的 DNS 状态。

正式策略 `src/lumabox/urls.py` 的 `AUDIO_HOSTS` 当前只有 `lf26-music-east.douyinstatic.com`。同一作品来源在已接受的 lf26 和未接受的 lf9 之间变化，足以解释此前成功而本次出现配乐地址校验失败的现象。

本次没有请求未支持节点的媒体文件，未确认 lf9 返回音频的实际内容、格式和解码；因此不能将该节点记为已验证支持。

## 诊断缺口与后续

域名策略拒绝没有附带具体域名和固定原因；`public_diagnostics` 对缺少 network_reason 的这类拒绝会清空细节，网页附件又只保存 audio_error。结果是音乐域名未覆盖与 DNS 非公网都映射成同一个笼统提示。

后续应先验证页面实际返回的 lf9 音乐资源，再更新音乐 CDN 的支持范围；同时持久化脱敏的配乐诊断，区分“音乐域名尚未支持”和“DNS 返回非公网地址”等原因。修复后只需为已有图集补保存配乐，无需重下图片。公网 DNS、HTTPS、作品对应关系及完整性检查继续保留。

临时观察及跟踪结果在忽略目录 `Downloaded/gallery-music-probe/`，没有保存或输出签名媒体 URL。本次观察到的 Windows 10054 浏览器关闭回调沿用旧问题，已确认的拒绝点是音乐域名校验。
