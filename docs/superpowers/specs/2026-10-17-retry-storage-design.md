# LumaBox 0.5：下载稳定性与文件管理设计

日期：2026-10-17。状态：用户已回复“执行”，设计已确认；实施计划待审阅，尚未开始产品实现。

用户选择按 **A → B** 推进：先改善下载稳定性，再补云端空间和文件管理。继续服务个人使用，兼顾 Windows 本地网页和现有 Linux 云端网页。

## 当前基础与本次目标

0.4.5 已完成普通视频、12 张图集、单页动态照片、云端登录及 Safari 请求兼容的验证。网页已有手动重试、取消、标题和进度、预览、搜索及分页。本次复用这些流程。

目前有三个实际缺口：临时失败只能手动再试；再次提交同一作品可能重新下载；移除记录只隐藏历史，实际文件仍占空间，而且旧隐藏记录没有管理入口。

本版成功标准：可恢复的临时故障最多自动补试一次；已有作品能被发现并复用；页面能够解释空间占用，并让用户明确选择保留文件或删除文件。先完成 A 的测试，再完成 B，最后整体验收。云端升级、源码推送仍在结果可审阅后按用户指示进行。

## 方案选择

- 只增强提示：改动小，但临时失败和空间回收仍需要用户手动处理。
- **增强现有队列和存储管理：本次采用。** 沿用 SQLite、单个 worker 和独立 CLI 子进程，在现有边界内增加重试、判重及删除状态。
- 引入新的任务队列、独立存储服务或多用户系统：超出个人工具当前需求，本次不采用。

## A：有限自动重试

### 用户可见行为

首次尝试失败后，符合下列条件的任务等待 **10 秒**，自动重试 **1 次**。每个逻辑任务最多尝试两次，保留在同一张任务卡；显示失败原因、“10 秒后重试”和“第 2 / 2 次尝试”。最终仍失败时提供已有的手动重试入口。

等待重试期间可取消。继续保持串行处理：该任务等待的 10 秒占用当前处理位置，后续任务最多多等这 10 秒。首版优先使用这个简单且可解释的规则。

自动重试使用原任务的视频大小上限，重新启动独立匿名浏览器和下载子进程，重新获取当前媒体地址，不续传失败的文件。手动重试仍按表单当前上限创建新任务。

### 重试条件

只对以下明确的临时故障补试：

- 网络诊断为 `CONNECTION_RESET`、`CONNECTION_TIMEOUT` 或 `DNS_TIMEOUT`，且发生在网页读取或媒体传输阶段；DNS 超时允许发生在解析阶段。
- `RESOURCE_TIMEOUT`：页面或媒体资源等待超时，且没有同时报告下面的禁止重试原因。

禁止自动重试的条件优先于允许条件。需要登录、访问验证、平台拒绝或限流、非公网地址、TLS 错误、连接被拒绝或网络不可达、作品不可访问、大小超限、空间不足、未知解析错误、完整性检查失败、缺少依赖、用户取消和服务中断均立即结束。没有结构化原因的通用 `DOWNLOAD_FAILED` 也不盲目重试。

单任务原有 **60 分钟总期限**覆盖两次尝试及等待时间，不在重试时重新计时；总期限耗尽后结束。临时文件必须清理成功才允许第二次尝试，避免新旧结果混合。清理失败保留明确提示，不以增加重试掩盖故障。

### 状态与持久化

新增 `retry_wait` 状态。典型流转为：

`pending → running → retry_wait → running → success / failed`

`retry_wait` 可直接取消；`running` 仍先进入 `cancelling`，待进程回收和临时文件清理后进入 `cancelled`。等待重试算作当前处理任务，一次仍只有一个处理位置、最多 10 个排队任务。旧有搜索、筛选、取消、清理、移除和队列计数需覆盖该状态。

在 SQLite 保存尝试次数、下次尝试时间、初次开始时间、总截止时间和有界的尝试结果。最多保留两次尝试的时间、固定错误码及现有脱敏诊断，不保存响应原文、Cookie 或签名地址。每次尝试分别显示进度，第二次允许从零开始，避免被旧的单调递增校验拒绝。

服务在 `retry_wait` 期间重启：保留已消费的重试额度及原截止时间，按剩余等待恢复，不额外增加机会。重启时正在运行的任务继续按现有规则标为中断，不自动重新执行；等待队列照常恢复。关闭服务和取消操作都能立即打断等待。

## A：重复作品提示与复用

### 提交时判重

优先按已确认作品 ID 判重；短链尚未解析时，先按现有规范化短链判重。使用数据库事务处理重复点击，避免并发提交产生两份相同活动任务。

- 已有相同作品或相同短链正在等待、运行、取消或等待重试：指向现有任务，不再新增下载，也不提供强制并行下载。
- 已有相同作品成功保存且文件可用：展示“已保存”，可查看已有结果，或明确选择“重新下载”。
- 旧任务失败、取消、过期、文件已删除或现有文件不可读取：允许新建任务。
- 旧记录被移除但文件仍保留：提示已有文件，可恢复记录并查看，或选择重新下载。A 阶段先提供必要的恢复入口，B 阶段在文件管理中复用。

复用前检查现有产物仍位于当前输出目录、不是链接、可读取且大小与记录一致；不把仅有 `success` 状态当作文件可用。发布时已有的完整解码和哈希校验继续保留。若文件不可用，说明原因并允许重新下载；本次不在每次提交时扫描所有历史文件的完整哈希。

“重新下载”只跳过已完成结果的复用，不能跳过活动任务判重。新下载使用新任务目录，保留原结果，不覆盖以前的文件。选择重新下载时先提示将额外占用空间。

### 不同短链解析后的判重

两个不同短链可能指向同一作品，提交前不能据此判断。worker 在现有可信进度首次确认作品身份后再次检查；发现已有结果时尽早结束新子进程并清理本次产物，任务显示“已有收藏”并引用原任务。

这种情况下可能已开始少量页面读取或媒体传输，不承诺零请求。发布前还要做最后一次判重，防止进度报告与子进程退出之间的时序差异遗漏重复作品。不得只根据页面标题或不匹配的作品身份合并结果。

新增终态 `duplicate` 和 `duplicate_of` 引用；重复记录自身没有文件，也不伪装成一次新的成功下载。强制重新下载的意图持久化，并跳过已完成结果判重。引用的原结果若随后被用户删除，显示不可用及重新下载入口。

### 接口约定

保持新建任务成功时返回现有任务结构。重复提交用固定的冲突响应说明匹配类型和已有任务的有限元数据；前端显示查看、恢复或重新下载操作。客户端不能指定文件路径或引用任意文件。

`POST /api/jobs` 增加严格布尔值 `force_download`；活动任务始终不能被该参数绕过。恢复接口只恢复当前输出目录中仍有可用产物的已隐藏成功任务，不恢复已删除文件。

## B：空间展示与文件管理

### 空间面板

在现有侧栏增加简明空间概览，详细操作放入“文件管理”区域。手机宽度下内容纵向排列，不影响粘贴链接和查看任务的主要流程。

显示当前输出目录中的文件大小合计、已保存作品数量、已移除记录但仍保留文件的占用，以及该目录所在磁盘的系统可用空间。图集的原图、动态片段和 ZIP 都实际占空间，计数需包括它们。

这些指标含义保持分开：“收藏文件大小”不是整台服务器占用；系统可用空间也不是专属于光匣的配额。文件大小按当前文件实际长度合计，不宣称等于文件系统物理块占用。

输出目录中无法对应数据库任务的内容和未完成产物，计入“其他 / 临时文件”，但不提供一键删除未知文件。`WebData`、浏览器缓存、旧输出目录及命令行独立下载不计入当前输出目录合计；在面板说明统计范围。磁盘可用空间天然反映同一分区的其他使用。

统计结果缓存最多 30 秒，显示更新时间，可手动刷新；发布、清理、移除或删除完成后使相关统计失效。不随每两秒任务轮询递归扫描整个目录。扫描遇到文件消失或权限问题时返回“统计不完整”，不能显示一个假装完整的零。

### 管理列表

增加按作品管理的分页列表，默认列出已保存文件，支持查看“记录已移除但文件保留”的作品。显示标题或 ID、保存日期、文件数量、当前文件大小及记录状态；隐藏记录可恢复到收藏。

分页及占用来自当前输出目录的受控统计。文件不存在时显示实际情况，数据库中的旧大小可作为历史信息，但不能冒充当前占用。失败任务的残留目录纳入统计和可处理状态；未知文件只展示占用，不自动认领为作品。

### 两种明确操作

1. **仅移除记录**：沿用现有语义，文件保留，仍可在文件管理中找到和恢复。
2. **删除记录及文件**：确认框展示作品标题或 ID、实际文件数量、文件大小和“无法从光匣恢复”的提示。仅用户确认后发送删除请求。

本版按作品单独删除，不新增批量删除或定时自动删除。默认长期保留策略不变。被移除的旧记录可直接在管理区域选择彻底删除，解决已有隐藏文件无法回收的问题。

正在排队、运行、取消或等待重试的任务不能删除。正在通过网页下载或预览的文件也暂不删除，提示停止预览或等待传输完成后再试；后端根据文件租约判断，不能仅依赖按钮禁用。

删除只处理该任务在**当前输出根目录**内、能够证明归属的文件及产物目录。检查任务 ID、相对路径、目录边界和链接；遇到越界、符号链接、Windows junction 或无法确认归属的额外内容则拒绝，并提示需人工检查。不得按客户端传入的路径删除，不触碰迁移前保留的原件、数据库、凭据或其他项目。

### 删除状态与恢复

使用持久化的文件生命周期状态记录删除意图和结果，不用“历史已隐藏”代表文件已删除。开始删除前在同一锁下检查活动状态及下载 / 预览租约，记录意图，阻止新文件读取和结果复用；再执行文件删除。

只有确认目标文件已删除或本来不存在后，才完成记录清理并显示成功。部分删除、权限错误或磁盘异常保留待处理状态和必要的归属信息，允许重试；不提前报成功或丢失剩余文件索引。服务重启仅继续此前已确认的删除意图，正常成功收藏不会被顺带清理。

删除请求幂等；重复点击、两个页面并发删除以及与文件读取的竞争，均不能删除其他任务文件。报告“已删除文件大小”和重新读取的系统可用空间，不保证二者增减严格相等。

### 接口约定

- `GET /api/storage`：输出目录统计、磁盘可用空间、采样时间和完整性标志。
- `GET /api/storage/items`：受限分页查询，包括仍保留文件的隐藏记录和删除待处理项。
- `POST /api/jobs/{job_id}/restore`：恢复可用的隐藏收藏。
- `POST /api/jobs/{job_id}/purge`：明确确认后的单作品删除，返回完成或待处理结果。

上述接口沿用现有云端认证、本机 Host、同源 Origin、CSRF 和请求体限制。读取接口不执行删除；返回固定原因及有限元数据，不泄露原始异常、签名地址或凭据。详细存储扫描及删除逻辑独立放入存储管理模块，避免继续把全部职责堆入 `app.py` 和 `store.py`。

## 数据兼容与交付顺序

SQLite 使用可重复执行的增量迁移：旧任务默认已使用零次自动重试、没有重试等待或删除意图，既有文件和隐藏状态保持原样。新增状态须同步覆盖 API、筛选、队列、取消、重启恢复、清理和前端文案。旧版服务不能与新服务同时访问同一数据目录。

先完成 A：重试规则和状态、进度边界、判重与已有结果恢复、网页反馈；通过验证后完成 B：空间统计、包括隐藏收藏的管理列表、租约保护的明确删除。最后进行联合回归和真实下载验证。

升级前记录旧提交，备份 SQLite，并确认没有活动任务；涉及不可逆的实际文件删除时，不能把旧数据库备份当成媒体备份。部署失败恢复旧代码和数据库前，先核对是否已发生删除，避免恢复出指向已删除文件的假成功记录。线上部署和 GitHub 推送待本版结果可审阅后按用户指示执行。

## 验证标准

### A

- 首次连接重置或资源超时、第二次成功：同一任务卡、最多两次尝试、真实新子进程及干净目录，最终文件完整校验通过。
- 两次均失败：停止自动尝试，保留两次有限诊断和手动重试入口。
- 登录 / 验证 / 限流 / 超限 / 解析 / TLS / 非公网地址等禁止条件不会因附带诊断而触发重试。
- 等待时取消和关闭立即生效；重启不重置预算；总期限不会翻倍；尝试之间进度可从零开始。
- 相同链接、完整链接与短链、不同短链、重复点击及并发提交：活动任务判重，已有成功结果可复用，强制重下不覆盖旧产物。
- 隐藏记录、已删除文件、结果缺失和原结果被后续删除都有明确处理；晚到的取消不能被判重改成成功。

### B

- 原图、动态片段、ZIP、隐藏收藏、临时目录和未知文件分别计入正确口径；统计不完整时有标记。
- 移除记录后文件仍在，管理列表可找到并恢复；彻底删除后仅该作品的目标文件消失，统计刷新。
- 实际 HTTP 下载和 Range 预览持有租约时拒绝删除；断开连接及发送异常后释放租约，再次删除可完成。
- 路径穿越、符号链接、Windows junction、额外未知文件、活动任务、重复请求和并发删除均不会造成越界或误删。
- 删除中断和部分失败能够重启恢复或重试，状态与实际剩余文件一致；缺失目录可幂等完成。
- Chromium 和 WebKit 覆盖手机宽度下的重试状态、判重操作、空间管理及确认框，保留正常登录、预览和取消行为。

完整回归通过后，在云端用既有授权样本验证普通视频、图集及动态照片；故障重试主要用可控测试服务验证，不能靠反复访问抖音来制造限流。删除验收使用新生成的临时样本，不删除用户现有收藏。真实平台结果、离线回归和用户实机结果分别记录。

## 本版范围之外

VPN / 代理接入继续低优先级；域名 HTTPS 在备案审核完成后单独接入。本版不加入多用户、主页批量下载、断点续传、图片转码、定时清理、收藏批量删除或新的抖音登录方式。
